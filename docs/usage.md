# OpenAI 费用保护与用量

用户选定试用档：每案例 **8 USD**、整个 Demo 所属组织每天 **40 USD**、每月 **160 USD**。日／月按 UTC 切换，案例额度覆盖该案例全部访谈、重连、事实提取、报告生成与重试；不是每次重新进入页面就重置。

2026-10-29 新增的“录音转写＋会后报告”也使用这些限额。录音不启动 Realtime；结束后每个已校验 WAV 分段作为独立 `transcription` 调用预留费用，按音频时长记录估算，随后分批事实提取与报告仍分别计量。网络失败或无法验证上游结果时保留未知占用；需要明确重试，不能清零旧记录。前台仍隐藏费用。详见 [会谈录音说明](recording.md)。

仓库提交的示例配置仍为 `LLM_PROVIDER=mock`、`VOICE_PROVIDER=mock`，因此克隆后不会自动发起网络调用。本机已由用户授权显式切换为 OpenAI 并配置 `whisper-1` 输入转写，用于限额内真实测试；密钥仍只保存在 Git 忽略的本机配置中。模拟操作不创建付费调用记录；历史付费记录也不会因切回 mock 而清零。上线这份账本前的请求没有回填为已核对用量。

## 后台记录与配置

按用户最新要求，顾问、Charles 和客户页面均不展示“费用与用量”入口、费用面板、金额或 token 明细。账本仍保存在服务端 SQLite，继续区分已知估算、预留或待核对金额和可用额度，不会把未结算金额当作零费用。既有内部接口权限不变：顾问／Charles 仅有本人／已分配案例明细，组织日／月只提供汇总，管理员没有案例明细，客户模式和匿名接口没有账本。

服务端配置，重启后生效：

```dotenv
LLM_PROVIDER=mock
VOICE_PROVIDER=mock
AI_CASE_BUDGET_USD=8
AI_DAILY_BUDGET_USD=40
AI_MONTHLY_BUDGET_USD=160
OPENAI_VOICE_MAX_SECONDS=1200
```

受控本机测试需要显式使用 `LLM_PROVIDER=openai`、`VOICE_PROVIDER=openai`，并可设置 `OPENAI_TRANSCRIPTION_MODEL=whisper-1`。示例文件继续保持 mock；不要把本机密钥或真实启用状态提交到仓库。

预算值必须为有限非负金额，设为 `0` 会阻止相应范围内的 OpenAI 调用。页面没有修改额度入口，客户和模型无法提高额度。更换模型需先增加经核实的费率及测试；没有费率的模型会在联网前被拒绝。保留的 Gemini 适配不在本轮 OpenAI 计费保护范围内，不能将这些额度当作 Gemini 或账户级通用限制。

## 计量和停止规则

- SQLite 保存调用和用量事件，金额采用整数微美元；与现有数据库一起备份。记录模型、用途、案例／访谈标识、请求标识、时间、token／音频分项、费率版本和状态，不保存密钥、提示词、客户原文或音频。
- 请求前在事务中同时检查案例、日、月余额并预留额度。并发调用共享同一账本。响应包含有效 usage 时，按完整输入（含历史）、输出、缓存和音频分项计价；响应拒答、被打断或输出格式失败也不能抹掉已发生的用量。
- 每次文字调用预留 $0.05，限制请求体最多 64,000 UTF-8 字节、输出最多 2,048 token。输出上限包含模型推理 token。完成后按返回 usage 结算，多余预留释放。
- 语音在建立 OpenAI 连接及生成首问前预留三层剩余额度。每轮输出最多 512 token，额外限制连接时长。接近预留额度或达到时长限制时停止转发音频、取消回复并终止连接，保留已有对话。
- 同一访谈异常断线后，重连先等待上一条连接安全收尾，再申请新预留；另一页面已有活跃连接时明确提示，不抢占连接。不会为了重连提前释放旧预留。调用限制、待收尾、用量不完整、时长和服务账户故障使用不同安全提示，界面仍不展示费用明细。
- Realtime 的每个 response 和客户转写分别计量并去重。`whisper-1` 只负责 Realtime 客户输入转写，当前按 **$0.006／分钟**估算；它不是负责上下文理解、下一问和语音回复的独立全链模型。Realtime 模型的输入、缓存、输出文字和输出音频仍按其 usage 另行计费。流式估算用于尽早停止；官方事件 usage 用于记录已知费用，不能只按最后一句转写时长计算整场费用。
- 发出请求后遇到网络失败、缺少／不合法 usage 或断线，保留未确认预留，标为待核对；重启不会清掉这些占用。待核对金额在跨日／跨月后仍占可用额度，以免通过重启或重连绕过保护。
- 超限阻止后续调用，文字回答先保存；后台任务保留失败状态，可在人工核对账单／调整额度后明确重试，不自动切成模拟 AI。待核对记录不能凭“没有收到回答”认定免费；仅完整完成凭据或经管理员核对确认的最终金额可以结算，没有按时间清零入口。

这是**应用级支出保护**，不是 OpenAI 账单的绝对硬封顶。实时上游处理、断线、延迟 usage、公开费率变化和其他使用同一账户密钥的程序都可能造成账单差异。必须保留这项限制，不能仅凭模拟测试宣称真实账单封顶已验收。

## 自动核对与人工结算

同日后续操作：用户明确要求释放另外两笔并保留已知费用。经副本演练、在线备份和事务内 27 表比较，两笔共解除 $3.966364 占额，保留 $0.033636 已记录费用和原用量事件，各新增一条授权审计。至此三笔历史调用累计解除 $4.958676 本地预留，仍保留 $0.041324 已知费用及 unknown 最终账单状态；三笔 held 均为 0。运行中上限再次核对为 $8／$40／$160，未新增付费调用。以下第三笔记录描述的是此前操作时点。

2026-10-29 本机运维例外：用户明确要求释放历史预留后，第三笔已结束的语音调用解除 $0.992312 本地占额，保留 $0.007688 已记录费用、全部 5 条用量事件及 `unknown` 状态。这是一次有备份、账本比较和 `usage.hold_released_by_owner` 审计的用户授权例外，**不是最终账单核对、零费用结算或 OpenAI 退款**。原预留 $1 记录在审计中；缺失部分尚未计入已知费用，后续取得证据仍须补记差额。自动规则没有放宽，其他两笔合计 $3.966364 仍占额，$8／$40／$160 配置未变。

管理员账号进入系统配置页，在“调用对账与结算”查看待核对调用。这里只显示财务信息，不提供客户档案、对话或报告；其他角色不能调用结算接口。

1. 后台启动及每 30 秒检查完整用量完成凭据，也可点击“立即自动核对”。文字终态响应、完整语音收尾、成功转写或已证明尚未发出请求的调用，会先持久化完成凭据，再正常结算。进程若在二者之间中断，后台依照凭据与精确用量摘要补做结算。金额仍是批准费率下的估算，不冒充供应商最终账单。
2. 没有完整凭据的记录保留“待人工核对”。按 UTC 开始／结束时间、模型及供应商证据核对本次最终总额；一张日汇总或空白账单不能当成某笔调用免费。当前三笔历史记录不具备新增的完成凭据，因此不会因升级自动释放。
3. 选择“人工结算”，输入最终美元金额（最多六位小数）、官方凭据编号或导出文件引用、核对说明。金额不能低于已记录的保护金额；有差异须进一步查清，不能通过页面抹去已有用量。零金额也必须有依据并明确确认，表单不默认填零。
4. 先预览计入金额与可释放预留，确认后提交。预览签名有效五分钟，绑定操作者、组织、调用版本、金额与说明；任何变化或服务重启都需重新预览。事务保存结算与审计，网络重试使用同一请求编号，防止重复释放。
5. 人工金额是调用最终总额。迟到事件先补齐确认总额与事件合计的差额，不重复加算；新事件使记录重新进入待核对，若事件费用超过原确认总额须再次核实。案例彻底删除时清除关联凭据和结算历史，仅保留不关联客户的组织金额汇总维持费用保护。

本功能不申请管理员密钥，也不轮询云端账单。OpenAI [Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)需要管理权限并返回日汇总，没有本应用调用 ID，不能自动分摊为每笔 Realtime 的最终费用。Realtime 的逐次计量依据是 [response.done 的 usage](https://developers.openai.com/api/reference/resources/realtime/server-events)。缺失的历史 WebSocket 用量不会因为升级而补回。

## 费率与验证边界

费率快照为 `openai-2026-10-28-whisper`，当前允许 `gpt-6-luna` 文字、`gpt-realtime-2.1` 语音，以及语音会话中的 `whisper-1` 或默认 `gpt-4o-mini-transcribe` 输入转写。`whisper-1` 只接受按时长计量，费率为 $0.006／分钟；`gpt-4o-mini-transcribe` 保留既有 token／时长计量兼容。更换转写模型只影响客户输入转写费用，不包含 Realtime 回复费用。
