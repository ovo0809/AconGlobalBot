# 以客户目标为中心的简短访谈

## 2026-11-04：参考 Paradox 的对话流程增量

用户要求自然、少问、复用回答，且本轮不调用付费 API。参考范围为 [Conversational Apply](https://www.paradox.ai/products/conversational-apply) 的低摩擦采集与资料回写，以及 [Candidate Experience Agent](https://www.paradox.ai/products/candidate-experience-agent) 的既有系统协作、企业批准内容和人工交接。问题选择、记忆规则与次数限制为 Aeconn 自身设计，不能把招聘产品介绍当成保险业务或真实语音验收。

本次在现有单访谈 Agent 上补齐：

- **先复用再追问**：从当前案例最终客户自述中识别明确表达的主题，保留消息来源与片段。它是只读对话记忆，不是事实表；客户仅提及主题、提出问题、顾问更正或临时字幕不能被当作已经回答。已保存事实及明确冲突仍按原规则优先。
- **一次一个重点**：问题缩短，先回应本轮实际内容，再问与当前目标相关的一个缺口。金额仅澄清尚未说清的单位／周期等，不根据默认币种或跨句拼单位创建数值；未知／拒答和已补问项目留待核对。
- **同轮信息立即复用**：云端文字输出先校验回复安全性与所有事实来源，再用合并后的有效事实规划下一问；重复已回答主题、一次抛出多个独立问句或收尾后继续发问时，本地替换为合适下一步，不增加模型调用。原提取结果不因措辞替换而改变。
- **语音后续规划更新**：OpenAI 每条新最终客户转写保存后更新后续系统指令，失败保留原上下文，重复事件及过期结果不重放。更新不增加回复轮次，原知识快照与预算保护保持。Gemini 沿用原生对话和初始化提示，不发送未经验证的动态 setup。
- **够用就交接**：当前主题足够或客户希望停止时，保留有来源的简短摘要和待核对事项，提示点击结束并交还顾问。结束音频、后台报告、复核和发送仍由原业务流程负责。

原本“8 问评估、10 问收尾”的计数规则、四类报告分析及真实验收边界保留。模拟记忆能减少重复，但不能据此保证任意语言表达都会被识别，也不能把少问后的报告当成所有事实齐全。真实模型提问自然度、完整连续语音与目标手机表现需后续实测。

日期：2026-10-30。用户要求减少生硬、重复和不必要的问题，理解完整回答；支持长会谈不代表必须聊满一小时。

## GFI 公开资料与适用范围

本次按 Global Financial Impact（globalfinancialimpact.com）理解用户所说的 GFI，名称尚未经用户再次确认。公开页面中的方法定位只作设计参考，不将其产品营销、收益描述或销售承诺纳入客户回答及报告规则。

- [GFI Services](https://globalfinancialimpact.com/services/) 描述先了解客户的具体处境、目标和风险承受能力，再形成个性化策略。可借鉴的是先听目标、按相关性深入；不能由此推断其内部话术、规定问题数量或真实平均访谈时长。
- [GFI Financial education / customized strategies](https://globalfinancialimpact.com/fin/) 强调金融教育和个人目标。对应本 Demo：必要时简短说明为什么问，允许不知道或暂不提供，不推动具体产品。
- [GFI Lifestyle](https://globalfinancialimpact.com/lifestyle/) 的生活维度可启发关注家庭与日常安排，但不转为强制多段问卷，也不额外询问宗教等与本次目标无关的信息。

以下问题数量、收尾规则和话术示例是 Aeconn 本次设计，不声称是 GFI 官方标准，也不是完整保险适当性调查或业务审批。

## 本次发现

1. 旧 `orderFor()` 将入口优先字段之后追加全部 17 项，选长期照护仍会问到人寿、伤残、退休等其他主题。
2. 原语音提示要求直接提问、不要铺垫，又要求区分准确日期和大致时间，没有明确何时结束，容易形成逐项核对。
3. 实时连接的结构化资料是启动快照，新增回答还没有成为 `knownFacts`；模型须结合原生连续对话，而不是反复追问快照中的缺失字段。
4. 模拟流程只识别固定问句，金额解析不成功时会反复给通用补充要求；没有跳过和收尾界限。

## 当前规则

- 客户实际目标优先。入口决定初步相关主题；一般问题 4—8 个即可考虑摘要，关键歧义可再澄清最多 2 问。客户主动要求继续深入时允许展开；不追求固定时长。
- 单轮先理解客户已经回答的全部内容，简短承接重点，再选一个最有价值的问题。允许一条最终回答支持多个事实，但仍逐项检查来源。
- 已经明确的目标、时间、家人、现有安排不换词重复问。保留“大概／明年”等精度，不无理由追问是否准确值；金额仅补会影响理解的缺项。
- 客户不清楚保单责任时，已有保险与未知责任并存；不给付期、等待期、报销形式等连续追问，交给顾问看保单。
- 同一缺口最多补问一次。未知、拒答、暂未决定和仍不清楚的内容留待核对，不编造 `unknown` 事实、金额或日期，也不把省略项当零。
- 遇到两个不同数字先看用途、时间、币种与周期，不能一律判为矛盾。来源校验、金额格式和人工确认规则保持。
- 客户问进度或想停止时先回应意图。收尾给出简短已知／待核对摘要，提示补充或点击结束；实际停止音频、后台报告仍由现有结束流程执行。
- 其余类别的报告仍允许“资料不足”。减少提问不代表报告齐全、承保结论成立或可以自动发送邮件。

## 示例

客户：“我想明年安排长期照护，希望在家，不想拖累孩子。有保险，但不知道包不包照护。”

可回应：“您更在意留在熟悉的家里，也希望减轻孩子的负担。这份保险先交给顾问核对；除了它，您还有其他照护安排吗？”

不再拆问目标、开始时间、居住安排、担心什么、是否有保险；不继续追问未知保险责任的细节。后续根据回答决定是否问预算或直接总结，而不是沿固定清单补齐所有字段。

## 实现与验证边界

- `lib/interview.ts` 提供文字与语音共用的对话规则及 `conversationPlan`；保留全部事实字段供客户主动补充或顾问后续维护。模拟路径根据已知事实、主题尝试次数和本次 session 问题数决定下一问，10 个问题后收尾，不把历史 session 累计为当前次数。
- OpenAI／Gemini 在同一个访谈 Agent 中按共享规则理解自然语言；不新增规划模型、额外 API 调用或本地模型。`conversationPlan` 是候选与摘要依据，实时新增回答仍由模型结合会话判断。模型是否真正遵守问题上限属于行为质量验证，并非服务端强制计数截断。
- 模拟规则仍不是语义模型：自然改写问题的主题识别、任意表达的停止意图、多主题理解不能用模拟通过来证明真实模型表现。
- 金额中多数字、中文数量级或单位来源不足，仍可能不能进入结构化事实；保留转写供人工核对，不要求为了通过解析无限重问。不能把“少问”解释为降低事实来源校验。
- 本轮合成测试验证分支、已知信息复用、未知／拒答跳过、有界澄清、会话隔离、进度／停止不写事实及语音提示传递。真实 API、实体麦克风、目标手机、真实平均时长及 Charles 内容质量另行验证；详见 [工程记录](verification.md) 和 [验收账本](acceptance.md)。
