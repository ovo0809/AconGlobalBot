# 报告协作编排与阅读检查

## 实施范围 2026年11月4日

用户要求学习并把 doc-coauthoring 的逻辑用于 Aeconn 内部报告。阅读的官方来源为 [Anthropic doc-coauthoring](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)，获取日期 2026-11-04。本机未安装同名技能，本轮学习公开原版的方法，不安装或调用 Claude，也不把 Codex 技能当作产品已接入的模型能力。

适用方法分为上下文整理、逐节起草与精修、初次阅读者检查。应用沿用当前案例、已保存事实与顾问建档背景，六段报告、四类分析、原顾问及 Charles 审批、不可变版本和邮件 dry-run 均保留。未知、拒答、矛盾以及资料参考均不能成为编造客户事实的依据。

本轮按以下计划完成增量：

1. 用纯函数整理报告读者、用途、已知／未知／拒答／冲突字段和转写完整性，不引入原始未保存对话或联系方式。
2. 在现有一次报告模型请求中加入编排指导；按章节表达案例依据和局限，先完成细节再归纳摘要。模拟规则与真实适配均使用原业务边界，不增加模型请求或第二个访谈 Agent。
3. 对下一步问题排序与规范去重，仅展示最多三项；完整原始分析仍保留。新报告提供可独立理解的摘要，网页、PDF和邮件正文使用同一版本。
4. 生成后用本地规则检查章节、已知事实被列为缺失、来源、重复问题和明显显示异常，保存检查结果供顾问阅读。检查不代替语义准确性验证或人工业务批准；旧报告不补写或重算检查。
5. 增加针对性回归，再以合成案例、假上游、隔离数据库验证报告／PDF、版本、审批与 dry-run。不调用付费 API、不重生成真实客户报告、不修改费用模块；上限仍为每案例 $8、UTC 每天 $40、每月 $160。

验证时另给一个不继承本聊天的原生子代理，仅提供合成报告正文及读者问题，确认其能找到客户目标、事实依据、未知／矛盾与下一步。该项是本轮开发验证，不代表应用内已经增加独立模型审稿或 Charles 人工验收。

## 已实现与检查边界

`lib/report-editorial.ts` 提供纯函数简报、实际问句的优先排序及本地阅读检查；`buildReport` 固定新版本摘要和检查结果，模拟起草同时消除已知字段误列缺失与照护地点重复补问。云端报告在原一次请求中收到同样的写作方法指导，不收到未保存对话。UI 的“报告校对”位于内部报告内，供现有有权角色查看，客户模式没有新增报告访问。

校对覆盖六段非空、明显占位／异常字符、技术编号暴露、已知字段被误列缺失、实际问句过多或重复，以及缺少／跨案例／非最终／助手来源。小数金额不会因标点去重而合并。未知与拒答是合法事实状态，不能仅因此判为错误；零个补问也可以是合法结果。本地规则无法证明语义准确、资料完整或业务适合性，不替 Charles 批准。

新格式 `company-readable/4` 仅在后续生成新报告时使用；历史版本和已保存 PDF 不变。模型原始分析候选保留于报告数据，页面／PDF／邮件正文展示同一摘要及最多三个优先问题。顾问更正事实或 Charles 写复核意见后仍走原有新版本流程，本轮未增加自由改写已保存正文的入口。

## 本轮实际验证

- 定向回归先复现新编排尚未实现的失败；初读发现的重复问法与缺失范围矛盾另有失败用例，再修正行为。
- 最终完整单测 328/328、内部主流程浏览器回归 5/5、类型检查、lint、隔离生产构建与差异检查通过。
- 一份合成案例 PDF 为两页，已逐页目检；两次全新读者审阅只接触报告正文。第二次能定位目标、金额、未知／拒答、后续问题和草稿状态，确认不再重复地点／时间或误列一般缺失。
- 读者仍指出“明年”的具体含义、收入与债务口径、实际照护支持等需要人工核对。未据此补造事实，未把合成来源标为已核验或业务通过。
- 未新增真实 AI／语音请求、邮件、目标手机或 Charles 业务验收；未重生成现有客户报告。详见[验收账本](acceptance.md)及[工程验证记录](verification.md)。
