# 报告与 PDF 验证说明

## 范围

`lib/report.ts` 是确定性的 Demo 规则层。它只把已采集事实整理为四类人工讨论顺序，不选择具体产品、不报价、不核保，也不执行申请、转保、退保、rollover 或资金转移。规则版本固定标记为 `demo_unapproved/1.0`。

报告固定包含六部分：客户画像、四类初步方向、证据与理由、限制与缺失、下次问题、给 Charles 的交接摘要。客户和顾问的标识及联系资料由服务端关联对象写入，不交给模型猜测。报告、正文和 PDF 都绑定 `case_id`、`client_id`、版本与不可变快照 ID。

## 校验边界

- 四类分析必须各出现一次，状态仅使用数据契约中的五个值。
- 消息证据必须是当前案例的最终消息；临时转写不能作为证据。
- 已确认但无消息来源的字段可以使用 `fact:<key>` 引用；未确认字段不可以。
- 未知或拒答必须保存为 `null`，不能写成 `0`。
- `income`、`expenses`、`debt`、`reserve`、`assets`、`budget` 的数值必须为有限非负数，并包含币种及 `month`、`year` 或 `once` 周期。
- 冲突字段保留多条来源并返回“资料不足”，由人工澄清。
- 客户输入中的指令、收件人或产品文字不会改变系统配置。

## PDF 实现

PDF 由 PDFKit 服务端生成，使用仓库内嵌的 Noto Sans CJK SC Regular 字体，支持中文、自动分页和页码。字体来自 [Noto CJK 官方仓库](https://github.com/notofonts/noto-cjk/tree/main/Sans/OTF/SimplifiedChinese)，按随附的 SIL Open Font License 使用；许可证保存在 `public/fonts/OFL.txt`。

自动测试检查 PDF 文件头、非空体积、字体嵌入标记和长内容分页。工程验收还应通过 Poppler 将真实附件逐页渲染为图片，检查中文缺字、重叠、裁切、页码和段落换页。测试 PDF 只使用合成资料。

## 未验证事项

- Demo 规则未经 Charles 批准，不能用于声称业务准确率达标。
- 未使用真实客户资料验证，也没有进行法律、税务或保险产品适用性验证。
- 浏览器／手机下载预览由端到端测试覆盖；不同 PDF 阅读器的打印结果仍需在目标设备上检查。
