# Aeconn 投喂资料目录

这里用于存放供 Aeconn 后续整理、检索和接入 AI 的参考资料。

查看 [资料处理列表](资料处理记录/README.md)，可集中打开每份资料的提取正文、原图、核对记录和 Demo 检索证据。现有长期护理海报的文字见 [提取结果](提取文本/长期护理宣传海报.md)；这是一份已单独整理的文本，不代表新上传图片会自动识别。

> 当前 GitHub 仓库是公开仓库，上传的文件和提交历史对外可见。请只上传有权公开分享的资料或合成示例。客户身份信息、真实录音、保单、财务资料、内部机密、API 密钥等不要上传；仅删除文件也不会清除 Git 历史。

## 如何上传

1. 打开本目录，点击 **Add file → Upload files**。
2. 拖入可公开的资料，填写资料来源和用途，再提交。
3. 可以按主题自行建立子文件夹，例如产品说明、访谈示例、业务规则。

当前 Demo 可读取 UTF-8 的 Markdown、TXT 和 CSV。图片、扫描件、PDF 与 Word 可保存，但在转换为上述文本格式前不会被 AI 读取；当前不提供 OCR。`README` 和 `*.source.*` 说明文件不会作为业务正文传给模型。

建议文件名：`YYYY-MM-DD_主题_v1.md`。资料应尽量注明：

- 来源、作者或机构，以及公开链接（如有）。
- 发布或更新日期、版本、适用地区和有效期。
- 使用授权、是否为合成示例。
- 复核状态：待复核／已由 Charles 复核；仅在实际完成复核后标记通过。

复杂资料可附同名说明文件，例如 `产品说明.source.md`，记录以上信息。合成示范资料放在名称含 `demo_unapproved` 的目录，或在正文加入 `review_status: demo_unapproved`。

## 如何用于 AI

在文字回复、建立语音连接或生成报告时，Demo 会按当前案例选择少量相关片段；缓存超过 5 分钟后重新检查 GitHub 更新。已有语音连接保留建立连接时的资料上下文。文字与报告的 AI 引用保留文件、commit、行号和来源编号；语音记录提供给 AI 的参考片段，不声称已逐段验证使用。资料没有相关内容时不会强行引用。

资料中的内容是待核对参考，不能直接当作客户事实或自动批准的业务规则，也不能覆盖权限、费用保护和产品安全规则。示范规则保持 `demo_unapproved`，经 Charles 确认后仍需按实际批准范围接入；未知或冲突内容保留为待确认，不得补造。

详细运行边界见 [Knowledge 资料接入](../docs/knowledge.md)。
