# Knowledge 资料接入

Demo 从公开仓库 `ovo0809/AconGlobalBot` 的 `main/knowledge` 读取参考资料。文字回复、建立语音连接或生成报告时，如果缓存已超过 5 分钟，服务端会重新检查 `main` 的 Git reference，把资料版本解析为具体 commit SHA；没有访谈或报告请求时不会定时轮询。传给模型的来源链接也固定到该 commit 和行号，历史报告不会因后续编辑而指向不同内容。

连续语音在每次连接开始时选择并固定资料上下文；连接内不会随每句语音重新联网检索。暂停后重新建立连接会重新选取，符合刷新条件时同步更新。文字每轮、报告每版独立检索。语音字幕旁的“提供给 AI 的参考资料”表示当次上下文，不代表已证明模型逐段使用；文字与报告额外记录模型返回、经服务端检查的引用编号。客户接口只返回严格验证过的公开 GitHub 固定版本来源，不能通过网络响应读取本地测试资料或内部同步提示。

最终事实提取不接收知识资料。报告将模型判断与已保存事实、参考资料分开保存，PDF 与邮件预览使用同一版本快照。关键词检索不调用付费 API；提供的片段会增加现有访谈／报告请求的输入用量，仍走原账本、预留与 $8／$40／$160 保护。资料库不是完整语义检索，也不自动解析扫描件、网页链接或其他附件。

当前只读取 UTF-8 的 Markdown、TXT 和 CSV。单文件、文件数量、扫描总量和最终上下文均有限制；每个案例最多选取 4 个相关片段、约 6 KB。PDF 和 Word 会显示转换提示，不会被静默当作已解析；PNG／JPG 等图片和扫描件尚不支持 OCR，需另存文本正文后才能检索。`README` 与 `*.source.*` 元数据文件不进入模型上下文。疑似含 API 密钥或私钥的文件会被排除。

检索采用确定性关键词匹配。没有相关片段时返回空结果，不塞入不相关资料。GitHub 暂时不可用时只可使用同一仓库与分支上次成功缓存的快照，并把状态标成 `stale`；没有对应 GitHub 缓存时标成 `unavailable`，不会自动读取本地目录。短时间重复失败会复用明确的失败状态，避免连续请求。远程与本地缓存按来源命名空间隔离。缓存默认与 SQLite 数据文件位于同一目录，不进入 Git；读取缓存、GitHub 元数据、正文、目录数量和目录深度都有硬上限。

资料始终是待核对的外部参考：

- 不能成为客户事实，客户事实仍只能引用当前案例的最终客户消息或已有的顾问更正来源。
- 不能覆盖权限、费用保护、产品安全、事实来源或人工复核规则。
- 不能据此自动推荐产品、报价、承诺收益或核保结果，也不能执行申请、退保、转保、rollover 或资金转移。
- 文件路径或正文明确标记 `demo_unapproved` 时，报告与提示中继续显示为未批准的演示资料；其他资料也只标 `reference_only`，仓库文件自行声称“已批准”不会升级权限。
- AI 使用资料片段时必须引用完整 `SOURCE_ID`。报告应同时保留标题、路径、commit、行号和固定链接，便于顾问与 Charles 复核。

本地开发可设置 `KNOWLEDGE_REMOTE=off`，改读项目内的 `knowledge/`。需要隔离测试资料时，可把服务端环境变量 `KNOWLEDGE_LOCAL_DIR` 指向单独目录；该值不会发给浏览器。测试运行器默认禁用 GitHub 网络读取。无论使用默认目录还是显式目录，本地读取都拒绝符号链接和目录穿越。关闭远程只用于开发或离线检查，不代表 GitHub 资料已同步。
